# 维度 Rubric 评测报告检查表

## 上线前至少检查

- 单维度一致率：模型与人工在单条维度判断上的一致情况。
- 题目级一致率：同一道题按“任一维度错则整题错”的规则聚合后，人机结论是否一致。
- 召回率：人工判为不通过的记录中，Judge 识别出了多少。
- 误召率：Judge 判为不通过的记录中，有多少是人工认为不该拦截的。
- 适用率：排除“不适用”后，可被当前维度实际判断的样本占比。
- 按维度结果：准确性、完整性、帮助性分别查看一致率、召回率和误召率。

计算口径：

- 错误样本召回率 = 人工和 Judge 都判“错”的数量 / 人工判“错”的数量。
- 人工判“错”、Judge 判“不适用”属于漏判：计入错误样本召回率分母，不计入分子。
- 误召率 = 人工判“对”、Judge 判“错”的数量 / Judge 判“错”的数量。
- 通过率 = Judge 判“对”的数量 / Judge 判“对”或“错”的数量。
- 适用率 = Judge 判“对”或“错”的数量 / 全部记录数。
- 分母为 0 时返回 `null`，不要写成 0。
- 题目级结论按 `case_id` 聚合：任一维度为“错”则题目为“错”；否则任一维度为“对”则为“对”；全部为“不适用”才为“不适用”。

## 不要混用

- “不适用”表示当前维度用不上或证据不足，不表示“对”。
- 总体一致率高，不代表失败样本召回率足够。
- 开发集用于修改 Rubric，留出集用于验收新版本。

## 每次报告都要记录

- Rubric 版本；
- Judge Prompt 版本；
- Judge 模型版本；
- 参考材料版本；
- 数据集版本和切分；
- 本次修改针对的误判；
- 人工审批人和日期。
